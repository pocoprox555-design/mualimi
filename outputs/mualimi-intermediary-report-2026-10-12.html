Mualimi: rebuild the connector, not the teacher

Read-only investigation split across three independent agents; implementation by one editor. All paths below are relative to D:/NT/APP CHAT/.

Decision: rebuild the agent, index-access and tool adapters; repair the provider/browser transport locally. Rebuilding the whole application or the curriculum is unnecessary. Existing working-tree edits, deletions and modified curriculum indexes were already present before this work; they were preserved and are not claimed as new work.

1. Short application map

  • public/index.html, style.css, app.js, sw.js: composer, local conversation state, HTTP request, SSE display and cached application shell.
  • server.mjs: request validation, teacher prompt, provider configuration, SSE and question summaries.
  • lib/agent.mjs / provider.mjs: model turns, read-only tool execution, Chat Completions parsing, retries and continuation.
  • lib/tools.mjs / index.mjs / outline.mjs: curriculum catalog, page maps, search, complete page/range reads and stored outline lines.
  • lib/pdf-fallback.mjs / pdf-layout.mjs / text.mjs: stored extraction, PDF loading/rendering, geometrical text reconstruction and extraction diagnostics. page-kind.mjs supplies build-time metadata.
  • curriculum-library/: original PDFs, per-book extracted records, aggregate PDF index, generated search index/shards, outlines and enrichment. scripts/ builds/imports these assets; package.json / Dockerfile define build/runtime packaging. Historical reports and root Markdown files describe earlier revisions, not necessarily current behavior.
Student + original history→Server + short prompt→Model chooses↔Read-only library tools→Exact streamed output

Before this change, the same broad flow existed, but context pruning, derived text, prescribed workflow and browser transformations interfered inside it. No active keyword-based intent router or automatic book planner was found in the examined request path.

3. What was rebuilt and removed

  • lib/agent.mjs: a direct turn loop with complete tool results, parallel read execution, identical-read cache, transient interruption recovery and output-length continuation. No local context pruning, forced final answer, repeated-call blockade, arbitrary tool timeout or overall wall-clock deadline. One broad emergency limit: 4,096 turns. Transient failed streams still use bounded recovery, not unlimited paid retries.
  • lib/index.mjs: small cached metadata/source adapter plus unranked field-aware discovery. Removed the old postings-driven model path, evidence selection, rewriting and large retired ranking/excerpt blocks. Original extraction and derived metadata remain distinguishable.
  • lib/tools.mjs: eight compact read-only tools; retained names for compatibility. Complete pages/ranges/outline lines, explicit offsets, page-map conflicts, missing pages and PDF failures.
  • lib/provider.mjs: fixed JSON/interleaved tool collection; don't close incomplete calls; malformed streams fail visibly. Retain pre-output transient retries, respect capped Retry-After, record each attempt. No-text partial tool fragments do not prevent safe replay.
  • lib/pdf-fallback.mjs: unchanged stored-text access, separate live/stored versions, optional raw PDF text items, preview cache and explicit preview-resolution limits; cancel loading/render tasks where the PDF engine permits. Legacy ranked fallback search now delegates to the unranked path.
  • server.mjs / lib/http.mjs / lib/config.mjs: short teacher prompt, original user/history forwarding after validation, provider-authoritative context setting, 8,000-token default output, comprehensive question summaries and awaited SSE backpressure for text.
  • public/app.js / public/index.html / public/sw.js: literal output, corrected SSE data-line joining/errors, connection-idle failure, immutable retries, original historical image parts, no automatic image reinjection/storage pruning, coordinated asset cache version.
  • package.json / Dockerfile: remove redundant shard stage and browser-only verification invalidation. No dependency additions.

Untouched: original PDFs, per-book curriculum data, outline files, enrichment and generated curriculum assets. No commit, push, deployment, OCR run, test suite or security audit.

4. Current execution path

  1. Browser stores the student's exact text and original image parts in their turn; sends the live original conversation. Unsupported images are rejected with an explicit message rather than silently dropped.
  2. server.mjs:63–77,159–189 adds one short teacher prompt and streams provider text directly.
  3. lib/agent.mjs:42–166 requests a model turn. Only completed tool calls execute; complete results return in matching call order. The model decides the next action.
  4. lib/tools.mjs:24–43,60–173 provides catalog, page map, text/index search, stored page/range/neighbors, raw outline and original PDF page access. lib/index.mjs:90–139 returns stored text without runtime substitution.
  5. lib/pdf-fallback.mjs opens original pages when requested and explicitly separates text, storedText, optional original textItems and preview image. Empty extraction never becomes invented page text.
  6. Provider output limits trigger continuation; transient partial text can resume without replaying the already-displayed prefix. An unrecoverable failure preserves partial output and labels it incomplete outside the model text. One question.summary includes attempts, model time, tools/arguments/cache/result sizes/page identities and total/first-token timing.

6. Data reality and unresolved risks

  • Library snapshot: 21 books / 2,342 page records. Stored derived statuses: 1,857 clean, 227 OCR, 194 damaged and 64 no-text; 46 unknown printed numbers. All 21 named PDFs were present. Existence is not proof of successful rendering or content fidelity.
  • Inherited data accuracy: 1,784 aggregate fullText records differed from derived search text; 51 underscore-run pages showed collapse. Reading unchanged fullText eliminates runtime substitution, not earlier OCR/transcription defects. Hanafi's 45 pages have no stored text. Every page was not visually reviewed; exact religious quotations, dates, formulas and printed folios still require original-page verification.
  • Page identity: 2,289 stored mappings are labelled parser, seven outline-footer and 46 unknown. Parser/offset mappings are not necessarily observed printed folios. Conflicts are now explicit, but the mappings were not corrected or certified.
  • Preview fidelity: existing JPEG preview limits remain (up to 1.7M pixels, scale 1.6, data URL 1.5M characters), now disclosed. Fine marks may be unreadable. Raw PDF text items expose extraction, not missing glyphs or guaranteed reading order; no new OCR was performed.
  • Speed/memory: no live latency or memory benchmark. The new field-search projection is built once and warmed after startup; it retains normalized source/metadata strings. It avoids corrupted postings but could increase cold-start work/resident memory. PDF work stays globally serialized to avoid uncontrolled PDF memory growth. Quantitative speed improvement is not claimed.
  • Cache freshness: caches are process-local and expect immutable deployment assets. Replacing curriculum/PDF files inside a live process requires restart. Manifest entries lacking filenames now report unknown instead of false success; no new checksums or live-reload scheme was built.
  • Model/provider: a declared window can still be rejected by the real provider. Full evidence can exhaust that real window; the connector now reports refusal rather than deleting evidence. Provider handling of additional continuation system messages, tool-result images, and no-repeat continuation was not exercised. Repeated identical requests remain legal until the broad emergency limit, so a looping model can incur cost.
  • Browser/storage: no UI automation. Replies now show Markdown/LaTeX literally rather than prettified mathematical/quiz widgets. Browser storage quota or the 8MiB request limit can still reject very long histories/images; quota failure is explicit and no messages are pruned. Old saved conversations cannot recover image parts previously discarded. Large uploaded images still undergo the pre-existing resize/re-encode path (public/app.js); this was not redesigned.
  • Prior evidence across questions: the browser sends original student/assistant turns, not previous internal tool traces. A follow-up may require rereading source evidence; local caches reduce processing but do not eliminate model round trips. No server-side session database was added.
  • Build/deployment: full verification and container builds were not run; no source regeneration was requested. Existing build-time metadata sanitization remains, separate from now-unchanged model-facing source text. Production behavior and the earlier release-gate issues were not revalidated in this no-tests task. The local rebuild is not published.

7. Bottom line

The code was not merely a passive library desk: it changed evidence, constrained repeated reading, prescribed a workflow and rewrote displayed output. Those model-facing interventions have been removed from the active path. The rebuilt connector is substantially smaller and makes transport/source limits explicit. This is a local implementation with static compatibility checks—not a guarantee that inherited extraction or the live model is now perfectly accurate or fast.
